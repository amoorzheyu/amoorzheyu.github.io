事情是这样的。

Codex Desktop 这几天隔一会儿就给我来一句 Reconnecting。

刚开始我还以为只是网络偶尔抽风，等一等也就过去了。可它不是偶尔。写着写着断一下，准备执行命令时断一下，聊到正起劲时又断一下。

最烦的不是断开本身。

而是你不知道它什么时候会再来。

我最初的直觉是，代理有问题。桌面端能打开，不代表它里面每个需要联网的进程都拿到了代理配置。尤其本机既有 HTTP 端口，也有 SOCKS5 或 mixed 端口时，随手把 `7890` 填进去，可能刚好能用，也可能只是看起来像配置过了。

于是我没有继续猜端口，直接把排查交给 Codex。

发给它下面这段话就行。

```text
帮我修复 Codex Desktop 一直 Reconnecting 的问题。
请定位我本机正在使用的代理端口和代理协议，然后创建或更新 ~/.codex/.env，写入以下代理配置。不要写死 7890，请替换成实际端口；如果文件已经存在，保留其他配置。
HTTP_PROXY="127.0.0.1:<HTTP 或 mixed 端口>"
HTTPS_PROXY="127.0.0.1:<HTTP 或 mixed 端口>"
ALL_PROXY="socks5h://127.0.0.1:<SOCKS5 或 mixed 端口>"
NO_PROXY="localhost,127.0.0.1,::1"
写入后检查配置是否正确
```

这段提示词里，我觉得最关键的是两件事。

第一，不要写死端口。

网上很多教程会直接让你填 `7890`，这对某些默认配置当然没问题，但代理客户端、订阅和规则都可能改过端口。配置错了，表面上 `.env` 文件是有了，Codex 还是照样重连，排查反而绕远了。

第二，让它保留原来的配置。

`~/.codex/.env` 不一定是一个空文件，里面可能已经有你自己的环境变量。只补充或更新代理相关的四项，比整份覆盖踏实得多。

Codex 会去确认本机当前实际监听的端口和协议，再把 HTTP 代理、HTTPS 代理和 SOCKS5 代理分别写好。这里的 `socks5h` 也别随便省掉，域名解析跟着代理走，在一些网络环境下会少很多莫名其妙的问题。

文件写完之后，还差最后一个动作。

彻底退出 Codex Desktop，再重新打开。

不是关掉当前窗口，不是留在后台。要确保应用进程真的退出，因为已经启动的桌面端通常不会重新读取刚写进去的环境变量。重新启动后，让它从干净的进程环境里拿到新的代理配置。

我这样处理之后，那个反复出现的 Reconnecting 就消失了。

回头看，这个问题并不复杂。难就难在我们总会先怀疑服务、网络或者客户端，忘了桌面应用和命令行一样，也需要明确知道该从哪条路出去。

所以下次再看到 Reconnecting，不妨先把代理端口和协议这件小事确认清楚。

有时候，真正卡住你的不是网络。

是那一行没被进程读到的配置。
